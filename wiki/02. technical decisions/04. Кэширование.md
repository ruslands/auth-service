# Technical Decision: Использование Redis для кэширования

## **Цель**

Обеспечить хранение часто запрашиваемых данных в кэше, чтобы:
- Уменьшить нагрузку на базу данных
- Ускорить время ответа API

## **Проблема**

- Часто запрашиваемые данные (например, сессии) в данный момент хранятся в базе данных.
- Enum-словари (например, роли и права доступа) хранятся в памяти приложения, что неэффективно при масштабировании.

## **Решение**

Использовать **Redis** как централизованное хранилище кэша.  
Redis развёрнут на сервере с помощью Ansible playbook.

## Текущее состояние

В Redis кэшируются следующие данные:
- Roles
- Permissions
- Resources
- Card enum

## Планируемое развитие

Добавить кэширование следующих сущностей:
- Сессии
- Enum для всех сущностей (в целях консистентности и масштабируемости)

## Дополнительные требования

- Реализовать **fallback** на базу данных в случае:
  - Отсутствия данных в кэше
  - Недоступности Redis
